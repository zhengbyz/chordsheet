# 开发笔记

项目的技术路线、分阶段发现，以及踩过的坑。评测数字见 [EVALUATION.md](EVALUATION.md)。

这些是开发过程中逐阶段记下的结论，包括**几个后来被数据推翻的判断**——
保留原判断和推翻它的证据，比只留下正确答案更有参考价值。


## 技术路线

```
音频输入
  ↓ librosa                  加载、重采样
  ↓ Demucs                   音源分离（人声/贝斯/鼓/其他）
  ├─ 全曲 → madmom           节拍 + 小节线（downbeat）+ 和弦
  ├─ 全曲 → librosa chroma   调式识别（Krumhansl-Schmuckler）
  └─ 人声轨 → basic-pitch    主旋律 → 音符
  ↓ pretty_midi              组装 MIDI
  ↓ music21                  → MusicXML
  ↓ MuseScore                → 五线谱 PDF
```

**核心原则：用现成预训练模型，不从零实现算法。**

## 各阶段实测结论

### 阶段 1 实测结论（2026-08-15）

代码在 `chordsheet/key.py`，`python -m chordsheet.key <音频>` 可直接跑。

**在 7 首真实钢琴曲上的表现，两套模板对比：**

| 指标 | 结果 |
|---|---|
| 调号一致 | **7/7** |
| 大小调一致 | 4/7 |
| 分歧类型 | 3 次全部是关系大小调混淆，无一次「完全不同的调」 |

所以工具**分两级报告**：调号当结论、大小调标注为不可靠。这不是保守，是数据要求的。
调号只取决于音级集合（哪 7 个音在响），大小调却要靠权重分布里主音的细微优势，
而主音常常还没三音响——实测某曲主音 B 只有 0.205，三音 D# 却有 0.517。

**HPSS 在独奏钢琴上是纯浪费**：占 91% 运行时间，开关两种 chroma 相关性 0.9998。
默认仍然开着（带鼓的编曲上有用），素材干净时加 `--no-harmonic` 快 10 倍。

~~**Temperley 模板比 Krumhansl 稳**~~ —— **这个判断已被真实标注推翻**，见上方
GuitarSet 评测。合成音频上 Temperley 领先幅度确实更大（+0.226 vs +0.078），
但那只是「它对自己的答案更笃定」；真实标注上 Temperley 全错 22 段、
Krumhansl 只有 10 段。默认已改回 krumhansl。
`--profile both` 仍然有用，两者打架就是「这段音频模棱两可」的信号。

**范围边界：假设整曲一个调**，不做滑窗分段分析。转调的曲子会被平均成四不像。
等阶段 2 做出小节线后，按小节窗口做分段调性分析更自然，届时再补。

### 阶段 2 实测结论（2026-08-15）

代码在 `chordsheet/beats.py`，`python -m chordsheet.beats <音频>` 可直接跑。
madmom 两段式：RNN 出逐帧概率（有噪声），DBN 在「速度 × 小节内位置」状态空间上
维特比解码（强加拍点等间距、速度平滑、小节线周期性三条先验）。

**合成音频 8/8**（4 个速度 × 2 个拍号）。相位误差 7-9ms，已压在 fps=100 的
10ms 帧分辨率极限上，不可能更准。

**7 首真实钢琴曲**：全部 4/4，速度稳定性 0.008-0.060，中间小节零不齐，约 6.6x 实时率。

**倍速/半速是本阶段的核心风险**，所以加了 librosa 起音包络自相关做独立交叉验证
（方法完全不同，没有共同失败模式）。它立刻在 `bgm_maoudamashii_piano11.mp3` 上
报警：madmom 80 BPM，librosa 161.5 BPM。

查证结果：**不是错误，是真实的节拍层级歧义**。慢速 93 个拍点全部嵌套在快速的
185 个里（比值 1.99），两种解读都自洽，分歧只在「把哪一层脉冲叫做拍」。
音乐上本来就没有唯一答案。

**但这对阶段 3 影响很大**：小节长度差一倍（3.00s vs 1.50s），和弦切片的粒度
跟着差一倍。遇到交叉验证报警的曲子，必须人耳定夺后用 `--min-bpm` 锁定。

**弱起要显式处理**：`bars` 从第一条小节线开始，之前的拍点不属于任何编号小节。
`anacrusis_beats` / `uncovered_head` 把这段暴露出来，否则阶段 3 开头会凭空少一段
而无人察觉。实测 `piano2_007.mp3` 有 3 拍弱起。末尾残片同理，见 `dropped_tail`。

### 阶段 3 实测结论（2026-08-15）—— 第一期目标达成

代码在 `chordsheet/chords.py`，`python -m chordsheet.chords <音频>` 跑完整流水线
（调式 + 小节线 + 和弦），输出「小节 → 和弦」。这就是第一期的「和弦谱生成器」。

**默认路线 cnn 在合成音频上 3/3**（C/F/G 三个调，各 8/8 和弦、8/8 小节对齐）。
`deepchroma` 路线有系统性弱点：**vi 级小三和弦一律判成 IV 级大三和弦**，
三个调各错两次、无一例外。所以默认用 cnn，deepchroma 只作对照。

**真实素材** `piano2_002.mp3`：两条路线逐小节 100% 一致，调内和弦 100%，
进行 `F G C C | F G C C`，与阶段 1 独立判出的 C major 互证。

#### 踩到的最重要的一个坑：合成音频的音色真实度

阶段 3 的神经网络对音色远比阶段 1、2 敏感。最初用 5 个等衰减正弦叠出来的音，
DeepChroma 在 Am 上输出 `C=0.93 A=0.92 E=0.60 F=0.59`——**凭空造出一个 F**，
于是 A-C-E 被读成 F-A-C。而同一段音频 librosa 的原始 chroma 是干净的
`A=1.00 C=0.84 E=0.77`。原因是这些模型在真实录音（Beatles / Billboard）上训练，
贫瘠音色属于分布外，DNN 会脑补成它熟悉的样子。

换成 12 个泛音 + 1/h^1.3 滚降 + 琴弦非谐性 + 逐泛音独立衰减 + 6ms 起音瞬态之后，
DeepChroma 给出 `A=1.00 C=0.99 E=0.99`，cnn 路线从 1/3 直接变 3/3。

**教训：合成音频测阶段 1（chroma 统计）和阶段 2（瞬态）没问题，
测阶段 3 必须用足够真实的音色，否则测的是「模型认不认识你的合成器」。**

#### 其余已知限制

- **词汇表只有 25 类**：12 大三 + 12 小三 + N。七和弦、挂留、减、增全部被压扁到
  最近的大/小三和弦。民谣和简单钢琴曲够用，爵士毁灭性。
- **vi / IV 混淆**是最常见的错误对（共享两音）。实测真实素材第 1、5 小节
  `F:maj 55% / D:min 45%`，几乎五五开。
- **和声节奏比小节快时一小节装不下一个和弦**，看 `mean_coverage`（小节内和弦纯度）。
  低于 70% 的小节会被单独列出。
- **阶段 2 的倍速歧义直接传导到这里**：小节长度差一倍，和弦切片粒度跟着差一倍。

## 已知风险

1. ~~**madmom 在 Python 3.12 上的兼容性未验证**~~ → **已解决（2026-08-15）**
   - 结论：**可用**，但必须装 git main 分支（`0.17.dev0`），PyPI 的 `0.16.1` 已死
   - 安装步骤和三个坑记在 `requirements-stage0.txt`，冒烟测试是 `scripts/stage0_madmom_smoke.py`
   - 实测：downbeat 推算 120.0 BPM（真值 120），和弦 I-IV-V-I 全对，CPU 实时率 2.8x
   - 遗留债：`setuptools<81` 的 pin 是权宜之计（madmom 依赖已移除的 `pkg_resources`）

2. **Demucs 只能跑 CPU** — 低端显卡显存不足以跑音源分离。一首歌预计数分钟，可接受但慢

3. **五线谱质量** — MIDI 转记谱涉及时值量化、等音记法、声部分配，自动生成的谱子常「技术正确但不可读」，是打磨地狱

4. **需要 ground truth 才能评估** — 参考数据集：Isophonics（和弦标注）、MedleyDB（旋律标注）、MAESTRO（钢琴）

## 概念澄清

项目最初的设想是「根据低音部分判断和弦」，这个思路需要修正：

- 低音提供**根音**，但和弦性质（大/小/减/七）需要完整和声信息
- 主流做法是提取 **chroma（12 维音级轮廓）**特征做模板匹配或神经网络分类
- 低音可作为**辅助特征**提升根音准确率，不作主要依据

## 素材选择

**从简单开始**：独奏钢琴或结构清晰的民谣。编曲复杂的流行歌留到流程跑通之后。
